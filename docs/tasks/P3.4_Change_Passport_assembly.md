P3.4 — Change Passport assembly
Write a function that takes one event cluster (from P3.2), its confidence object (from
P3.3), and the relevant ancillary data (rainfall, slope, seismic history, data
provenance manifest from Phase 1), and assembles a complete, schema-valid Change
Passport JSON object exactly matching this schema: [paste the full Change Passport
JSON schema from Part 3 of this document here]. Validate every assembled object
against a JSON Schema definition of the above (write the JSON Schema file itself first,
then validate against it) so a malformed Change Passport fails loudly at assembly time
rather than silently reaching the frontend.

Acceptance criteria: every Change Passport produced by the pipeline validates against
the JSON Schema with zero errors; running this on real processed AOI data produces at
least one real, complete Change Passport object you can visually inspect and confirm
makes physical sense (e.g., a cluster with high coherence and multiple observations
should not report a Low confidence tier without an explainable reason in
cross_source_agreement).
