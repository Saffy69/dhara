# P7.2 — Community observations endpoint

P7.2 — Community observations endpoint
Implement the POST /observations endpoint to accept a field report: {event_id (optional,
nullable if the report isn't tied to a specific known cluster), lat, lon, description
(free text, max 500 chars), reporter_contact (optional), timestamp}. Store submissions
in the database. Add basic abuse protection (rate limiting per IP, and reject empty or
obviously spam submissions) since this endpoint has no authentication in the MVP. Add a
GET /observations?event_id={id} endpoint so the frontend can display prior reports tied
to a given event.

Acceptance criteria: a real POST request with valid data succeeds and is retrievable
via the GET endpoint; a request with an empty description or an out-of-range lat/lon is
rejected with a clear 4xx error, not silently accepted.
