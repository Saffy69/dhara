# P0.1 — Repository structure

P0.1 — Repository structure
Set up a monorepo for a NASA Space Apps Challenge project called DHARA. Create this
top-level structure:

/data-pipeline (Python: acquisition, preprocessing, change detection, confidence scoring)
/api (Python FastAPI backend)
/frontend (React + TypeScript, Vite, MapLibre GL JS, Recharts)
/docs (methodology, architecture diagrams, README assets)
/notebooks (exploratory Jupyter notebooks, kept OUT of the production pipeline)

Initialize each with its own dependency management (pyproject.toml or requirements.txt
for Python, package.json for the frontend). Add a root README.md with a one-paragraph
project description, and a CONTRIBUTING.md describing a feature-branch + PR workflow
(no direct commits to main). Add a sensible .gitignore for Python, Node, and common
geospatial temp files (.tif, .h5, .nc should be gitignored by default, with a
data-pipeline/data/.gitkeep to hold a place for local data that is not committed).

Acceptance criteria: repo builds/installs cleanly with no manual fixes; README explains
the project in under 200 words; a new contributor could clone and run `pip install` /
`npm install` in each subfolder without errors.
