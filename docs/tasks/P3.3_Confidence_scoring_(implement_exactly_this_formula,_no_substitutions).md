P3.3 — Confidence scoring (implement exactly this formula, no substitutions)
Implement the DHARA confidence model exactly as specified — this is a weighted sum,
NOT a product, of five independently normalized (0 to 1) components:

confidence = 0.25 * data_quality
           + 0.25 * temporal_persistence
           + 0.20 * spatial_coherence
           + 0.15 * cross_source_agreement
           + 0.15 * model_validity

Define each component precisely:
- data_quality: fraction of non-masked, PROVISIONAL-or-better pixels in the cluster
- temporal_persistence: fraction of available time steps in which the anomaly re-appears
  in the same cluster location
- spatial_coherence: mean InSAR coherence value across the cluster's pixels
- cross_source_agreement: score by how many of 3 independent checks pass — recent
  rainfall spike above a documented threshold, slope from DEM above a documented
  steepness threshold, and known seismic history within the last N years — mapped to
  0, 0.33, 0.67, or 1.0 for 0, 1, 2, or 3 checks passing
- model_validity: 1.0 if the cluster falls inside the validated Sentinel-1 historical
  test region, else a documented lower default (0.6) for live/unvalidated NISAR-only
  clusters

Map the resulting overall_score to a tier: High >= 0.75, Moderate 0.5-0.75, Low < 0.5.
Write this as a single, well-tested, pure function that takes a cluster's raw inputs
and returns the full confidence object matching the Change Passport schema's
"confidence" field exactly (overall_score, tier, and all five named components — never
collapse this into just the tier).

Acceptance criteria: unit tests exist for at least 5 synthetic input cases spanning
High, Moderate, and Low tiers, and confirm the weighted-sum formula (not a product) is
what's actually implemented; a code reviewer should be able to trace any overall_score
back to its five component values without re-running anything.
